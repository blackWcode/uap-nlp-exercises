01 · The project

Course exercises, real UAP texts

This notebook recreates Exercises 1.2 and 1.3 of the openHPI course Knowledge Graphs – Foundations and Applications, using texts from UAP (unidentified anomalous phenomena) reports instead of the course examples.

It tests how standard NLP tools handle these texts: messy historical reports, non-English place names and ambiguous words. Getting entities and word meanings right is an early step towards building a knowledge graph from UAP reports.

A learning project. Results come from one sentence or paragraph per test, so they show behaviour on these examples, not general performance.

03 · Named entity recognition

Can the model find four Brazilian states?

The same sentence from the gov.br article, run through each step of the notebook. Choose a step to see what the model labelled. These are the actual outputs.

  • GPE: places
  • PERSON
  • ORG
  • DATE · CARDINAL · QUANTITY
  • Missed

Gazetteer (GeoText)

Found São Paulo, Rio de Janeiro and Goiás, but labelled them as cities, because cities with those names exist. It missed Minas Gerais. A list of names cannot use context to decide what kind of place something is.

Generalisation test

On five “Washington” sentences the medium model was already correct, so the context rule changed nothing. It did not turn people into places, but it has not yet been shown to fix errors in new sentences.

04 · Word sense disambiguation

A “light” in the sky, or a torch?

The Lesk algorithm picks a WordNet meaning by counting words a definition shares with the sentence. Here is what it chose.

“The pilot observed a bright light moving across the sky.”

Lesk chose

Wrong

A quality cannot move across the sky.

“The investigator used a light to examine the aircraft.”

Lesk chose

06 · Findings so far

What the notebook shows

  1. 01

    The spaCy models struggled with Brazilian state names: each labelled only one of the four correctly, likely because they were trained on English web and news text.

  2. 02

    A rule-based list fixed all four states, but it only works for the exact names on the list.

  3. 03

    A context rule (names after in or over, or listed after states) corrected every wrong label without a country-specific list.

  4. 04

    The Lesk algorithm chose the wrong sense of light twice and of tracked in the radar sentence.

  5. 05

    On the Blue Book paragraph, a larger model did not perform better; all three scored 4 out of 8. They did better here than on the Brazilian text, which suggests they find English names more easily than Portuguese ones.

Limitations

  • Only one paragraph from the Blue Book file was analysed, so results may not hold for other reports.
  • The Blue Book text is a transcription, not the original scanned document.
  • The transformer model (en_core_web_trf) could not be loaded because of a Python 3.14 / PyTorch compatibility problem.
  • The expected labels were decided by one person; an independent second labeller would make them more reliable.
